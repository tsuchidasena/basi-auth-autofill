# Basic Auth Autofill

HTTP **Basic 認証**（ブラウザが出すネイティブなユーザー名/パスワードのダイアログ）に、
暗号化保存した資格情報を自動入力する Chrome 拡張機能です。

1Password などのパスワードマネージャーは、Basic 認証のダイアログがウェブページの DOM ではなく
**ブラウザ本体の UI** であるため入力できません。本拡張は `chrome.webRequest.onAuthRequired` を
フックし、ダイアログが出る前に資格情報を供給します。

## 対応環境

- **ブラウザ**: Google Chrome 108 以上（`webRequestAuthProvider` 権限のため）
- **OS**: 拡張本体は **Windows / Linux でも動作します**。ただし **Touch ID 解錠は macOS 限定**です
  （macOS の LocalAuthentication を使うため）。macOS 以外では Touch ID 関連の項目は表示されません

## 特長
- 🔐 マスターパスワードで AES-GCM 暗号化（PBKDF2 / SHA-256 / 250k iterations）
- 🧠 解錠中のみ鍵をメモリ（`storage.session`）に保持。ブラウザを閉じると要再解錠
- 🎯 host 単位のマッチング（完全一致 / ポート指定 / `*.example.com` ワイルドカード）
- 🔁 誤った資格情報での無限ループを防止（一度失敗したら手入力にフォールバック）
- 🍎 任意で **Touch ID 解錠**（完全ローカル / クラウドアカウント不要）。認証すると、
  そのとき開こうとしていたページがそのまま開きます（リロード不要）
- 📦 資格情報の**エクスポート / インポート**（暗号化ファイル。バックアップにも受け渡しにも）
- 🛠 ビルド不要。素の Manifest V3 + HTML/CSS/JS

## 1. インストール（拡張本体）

1. このリポジトリをダウンロード / クローンする
   ```sh
   git clone <このリポジトリのURL> basic-auth-autofill
   ```
2. Chrome で `chrome://extensions` を開く
3. 右上の **デベロッパーモード** をオン
4. **パッケージ化されていない拡張機能を読み込む** をクリック
5. クローンしたフォルダ（`manifest.json` がある場所）を選択
6. ツールバーにアイコンが出れば完了。固定しておくと便利です

> 💡 拡張 ID は `manifest.json` の `key` で固定されています。**フォルダをどこに置いても
> 同じ ID** になるので、移動や入れ直しで保存データが消えることはありません。
>
> ```
> lddkfmdklnjalpkojbfajlkcgghidjhc
> ```
>
> ただし保存データは**プロファイルごと**です。別の Mac や別の Chrome プロファイルに
> 移すときは、下記のエクスポート / インポートを使ってください。

## 2. 初期設定と使い方

1. アイコンをクリック → 初回は **マスターパスワード**（8文字以上）を設定
2. Basic 認証のあるサイトの資格情報を登録
   - ポップアップの「このサイトの資格情報を登録」から、または
   - 「すべての登録を管理」→ 設定画面でまとめて追加/編集
3. 以降、登録済みドメインで Basic 認証が出ると**自動でログイン**されます
4. ブラウザを再起動した後は、最初の認証の前にポップアップから **解錠** してください
   （Touch ID を有効にしていれば「Touch ID で解錠」が使えます）

### host の指定方法
| 指定 | マッチ対象 |
|---|---|
| `example.com` | `example.com`（デフォルトポート） |
| `example.com:8443` | ポート 8443 |
| `*.example.com` | `example.com` および全サブドメイン |

完全一致がワイルドカードより優先されます。

### 動作確認（任意）
同梱のローカルサーバで試すのが確実です（Node が必要）。

1. `node tools/local-401-server.js` を起動
2. host `localhost:8765` / ユーザー名 `user` / パスワード `passwd` を登録
3. 解錠した状態で `http://localhost:8765/` を開く
4. ダイアログが出ずに `{"authenticated": true}` が表示されれば成功

リクエストのたびに realm が変わるので、**何度でもやり直せます**。
公開の `httpbin.org/basic-auth/user/passwd` でも試せますが、応答が不安定なうえ、
一度通すと Chrome が資格情報をキャッシュするため再テストにブラウザの再起動が要ります。

## 3. 資格情報のエクスポート / インポート

設定画面から、登録済みの資格情報をファイルに書き出したり読み込んだりできます。
**自分のバックアップ**にも、**必要な分だけ他の人に渡す**のにも使えます。

### エクスポート

1. 設定画面を開く（解錠が必要です）
2. 「登録済みの資格情報」の一覧で、**渡したい行だけチェック**を残す（既定は全選択）
3. 「エクスポート」カードで**エクスポート用パスフレーズ**を入力（確認用にもう一度）
4. 「エクスポート」を押すと JSON ファイルがダウンロードされます

> ⚠️ **他の人に渡す場合は、マスターパスワードとは違う文字列にしてください。**
> マスターパスワードを使い回すと、ファイルを渡すことが「自分の金庫の鍵を渡す」ことに
> なります。
>
> ⚠️ **ファイルとパスフレーズは別の経路で渡してください。** 同じチャットに両方を
> 貼らないでください。

「暗号化せず平文で書き出す」チェックもあります。他ツールへの移行や内容確認に使えますが、
**ファイルを開けば誰でもパスワードを読めます**。ファイル名に `-PLAINTEXT` が付きます。

### インポート

1. 設定画面の「インポート」カードでファイルを選ぶ
2. 「読み込む」を押す（暗号化ファイルならパスフレーズを聞かれます）
3. 同じ host が既に登録されていた場合は一覧が出ます。
   **チェックした行だけが相手の内容で上書き**され、チェックを外した行は今の登録が残ります
4. 「取り込む」を押すと「取り込み / スキップ / 上書き」の件数が表示されます

既定では**上書きしません**。意図せず自分の資格情報が置き換わることはありません。

## 4. v0.2.x からの移行

**v0.2.x から v0.3.0 に上げるときは、順序を守らないと保存データが失われます。**

v0.3.0 で拡張 ID を固定した関係で、**アップグレード時に一度だけ ID が変わります**。
Chrome は ID ごとに保存領域を分けているため、旧 ID のデータは新しい拡張から読めません。

必ず**この順序**で行ってください。

1. **先に旧バージョン（v0.2.x）で全件エクスポートする**
   … と言いたいところですが、v0.2.x にはエクスポート機能がありません。
   登録件数が少なければ**手元にメモを取ってください**。多い場合は、
   一度 v0.3.0 を**別フォルダに追加で読み込み**（旧 ID の拡張はそのまま残ります）、
   旧拡張の設定画面を開いて内容を確認しながら新拡張に登録し直すのが確実です
2. **`chrome://extensions` で旧バージョンの拡張を「削除」する**

   > ⚠️ ここで「再読み込み」を押してはいけません。ID が変わるため、Chrome のプロファイルに
   > **旧 ID の登録が残ったまま新 ID の登録が追加され**、同じフォルダを指す登録が 2 つに
   > なります。この状態になると **Chrome を再起動するたびに拡張が一覧から消えます**。
   > 必ず削除してから読み込み直してください。

3. 拡張のフォルダを v0.3.0 に更新し、「パッケージ化されていない拡張機能を読み込む」で
   **改めて読み込む**（ID が `lddkfmdklnjalpkojbfajlkcgghidjhc` になります）
4. **Chrome を一度再起動し、拡張が消えないことを確認する**
5. マスターパスワードを設定し直す
6. 手順 1 で控えた資格情報を登録（またはインポート）する
7. Touch ID を使っている場合は、**新しい ID でネイティブホストを入れ直す**

   ```sh
   ./native/install.sh lddkfmdklnjalpkojbfajlkcgghidjhc
   ```

   実行後に **Chrome を再起動**してください（拡張の再読み込みだけでは反映されません）
8. 設定画面で Touch ID 解錠を有効化し直す

> 🔁 移行が済んだあとは、この作業は二度と必要ありません。以降は ID が固定されるので、
> フォルダを移動しても入れ直してもデータは残ります。

## 5. Touch ID 解錠の設定（任意・macOS のみ）

マスターパスワードの代わりに Touch ID で解錠できます。**完全ローカル**で動作し、
Apple ID や Google アカウントなどのクラウドには一切依存しません。

### 必要なもの
- Touch ID 搭載の Mac
- Xcode Command Line Tools（未導入なら `xcode-select --install`）

### 手順
1. ターミナルで、クローンしたフォルダ内の install スクリプトを実行：
   ```sh
   ./native/install.sh lddkfmdklnjalpkojbfajlkcgghidjhc
   ```
   → Swift 製ネイティブホストをビルドし、Chrome に登録します

   拡張 ID は `manifest.json` の `key` で固定されているので、**この値をそのまま**
   使えます（`chrome://extensions` で控える必要はありません）
2. **Chrome を再起動**（拡張の再読み込みだけでは反映されません）
3. 拡張のオプション → マスターパスワードで解錠 → **「Touch ID 解錠を有効化」**
4. 以降、施錠後にポップアップの **「Touch ID で解錠」** が使えます

### 認証が必要になったとき

Touch ID を有効にしておくと、施錠中に Basic 認証のあるページを開いた時点で
**その場で Touch ID が出ます**。指を置けばそのページがそのまま開きます（リロード不要）。

キャンセルしたり15秒放置したりすると、ブラウザ標準の認証ダイアログに切り替わり、
通知とツールバーの赤いバッジでお知らせします。**以降は繰り返し聞きません** —
ポップアップから明示的に解錠すると、バッジが消えて元の動作に戻ります。

詳細・仕組みは [`native/README.md`](native/README.md) を参照。

> ⚠️ **セキュリティ上の注意**: 鍵は login キーチェーンに保存され、**ハードウェア保護ではありません**
> （ハードウェア保護には有料 Apple Developer 署名が必要なため）。このユーザー権限で
> コード実行できる攻撃者は Touch ID を経ずに鍵を取り出せます。**at-rest 強度はマスターパスワード
> のみ運用に劣る**、あくまで利便性向けの機能と位置づけてください。

## セキュリティ
- パスワードは平文で保存しません。鍵はマスターパスワードから都度導出します（鍵自体は保存しない）。
- 解錠状態はメモリのみ（`storage.session`）。ブラウザ終了で破棄されます。
- マスターパスワードを忘れると復号できません。設定画面の **リセット** で全削除のみ可能です。
- content script からはアクセスできません（拡張内の信頼コンテキストのみ）。

## トラブルシュート
| 症状 | 対処 |
|---|---|
| 自動入力されずダイアログが出る | host が一致しているか / 解錠済みか確認 |
| 一度入れたら以後ダイアログが出ない | Chrome が資格情報をキャッシュ。シークレットウィンドウか再起動で再現 |
| ツールバーに赤い `!` が出ている | 自動解錠に失敗しています。ポップアップから解錠してください |
| 解錠したのに Touch ID が出ない | 一度失敗すると、明示的に解錠するまで再び聞きません（仕様） |
| `Specified native messaging host not found` | `./native/install.sh lddkfmdklnjalpkojbfajlkcgghidjhc` を実行したか / Chrome を**再起動**したか |
| 登録していないサイトでも Touch ID が出る | 施錠中は「その host の登録があるか」を判定できないための仕様です。キャンセルすれば以降は聞きません |
| Touch ID が出ない | システム設定 > Touch ID とパスコード を確認 |
| インポートで「対応していないファイル形式」 | この拡張がエクスポートしたファイルか確認してください |
| **Chrome を再起動するたびに拡張が消える** | 移行時に「削除」せず「再読み込み」したため、同じフォルダを指す登録が 2 つ残っています。`chrome://extensions` で**該当する項目をすべて削除** → Chrome を完全終了 → 起動し直してから**1 回だけ**読み込み直してください |

## 開発

拡張本体は**ビルド不要**です。以下は開発時のみ使います。

```sh
pnpm install                      # eslint（devDependency のみ）
pnpm lint
pnpm test                         # transfer.js の自動テスト
node tools/local-401-server.js    # 動作確認用の 401 サーバ（user / passwd）
```

`http://localhost:8765/` で単発の Basic 認証、`/multi` で 401 を返すサブリソースを
5つ持つページを返します。リクエストごとに realm が変わるので、Chrome の認証キャッシュに
邪魔されずに何度でも試せます。

## 制限事項 / 今後
- プロキシ認証（`isProxy`）の自動供給は対象外（コード上に枠のみ）
- `chrome.storage.sync` による端末間同期は未対応（エクスポート / インポートで代替）
- ハードウェア保護の Touch ID は未対応（有料 Apple Developer 署名が必要なため）
- マスターパスワードを忘れた場合の復旧手段は未実装（リセット＝全削除のみ）
- 「施錠しない」設定は未実装（仕様は `PROJECT_SPEC.md` に確定済み）
