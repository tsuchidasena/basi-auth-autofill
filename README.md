# Basic Auth Autofill

HTTP **Basic 認証**（ブラウザが出すネイティブなユーザー名/パスワードのダイアログ）に、
暗号化保存した資格情報を自動入力する Chrome 拡張機能です。

1Password などのパスワードマネージャーは、Basic 認証のダイアログがウェブページの DOM ではなく
**ブラウザ本体の UI** であるため入力できません。本拡張は `chrome.webRequest.onAuthRequired` を
フックし、ダイアログが出る前に資格情報を供給します。

---

## 初めて導入する方へ

この順に進めてください。**5分ほどで終わります。**

1. リポジトリを clone する
2. `chrome://extensions` でデベロッパーモードをオンにし、**`extension/` フォルダ**を読み込む
3. ツールバーのアイコンをクリックして**マスターパスワード**を決める
4. （Mac のみ・任意）**Touch ID 解錠**を設定する — 設定画面が案内します
5. Basic 認証のあるサイトを普通に開く。**未登録なら「登録しますか？」と聞かれます**

詳しくは下の 1〜3 節を順に読んでください。

## 対応環境

- **ブラウザ**: Google Chrome 108 以上（`webRequestAuthProvider` 権限のため）
- **OS**: 拡張本体は **Windows / Linux でも動作します**。ただし **Touch ID 解錠は macOS 限定**です
  （macOS の LocalAuthentication を使うため）。macOS 以外では Touch ID 関連の項目は表示されません

## 特長
- 🔐 マスターパスワードで AES-GCM 暗号化（PBKDF2 / SHA-256 / 250k iterations）
- 💡 登録し忘れを検知して**その場で登録を提案**（host は埋まった状態で出ます）
- 🍎 任意で **Touch ID 解錠**（完全ローカル / クラウドアカウント不要）。認証すると、
  そのとき開こうとしていたページがそのまま開きます（リロード不要）
- 🧠 解錠中のみ鍵をメモリ（`storage.session`）に保持。ブラウザを閉じると要再解錠
- 🎯 host 単位のマッチング（完全一致 / ポート指定 / `*.example.com` ワイルドカード）
- 📦 資格情報の**エクスポート / インポート**（暗号化ファイル。バックアップにも受け渡しにも）
- 🔄 サイト単位の**常にハードリロード**（開発サーバで古いレスポンスを掴まされない）
- 🛠 ビルド不要。素の Manifest V3 + HTML/CSS/JS

## 1. インストール

1. このリポジトリをダウンロード / クローンする
   ```sh
   git clone <このリポジトリのURL> basic-auth-autofill
   ```
2. Chrome で `chrome://extensions` を開く
3. 右上の **デベロッパーモード** をオン
4. **パッケージ化されていない拡張機能を読み込む** をクリック
5. クローンしたフォルダの中の **`extension/` フォルダ**を選択（リポジトリのルートではありません）
6. ツールバーに青い南京錠のアイコンが出れば完了。固定しておくと便利です

> ⚠️ 選ぶのは **`extension/` だけ**です。リポジトリのルートには開発用のファイル
> （`node_modules/` など）が入っており、これを読み込ませると
> **Chrome を再起動するたびに拡張が消えます**。
>
> 💡 拡張 ID は固定されているので、フォルダをどこに置いても、移動しても保存データは消えません。
> ただし保存データは **Chrome のプロファイルごと**です。別の Mac やプロファイルに移すときは
> 「4. 資格情報の受け渡し」を使ってください。

## 2. 初期設定

### マスターパスワード

ツールバーのアイコンをクリックし、**マスターパスワード**（8文字以上）を決めます。
資格情報はこれで暗号化されます。**忘れると復号できません**（リセット＝全削除のみ）。

### Touch ID 解錠（macOS のみ・任意）

マスターパスワードの代わりに Touch ID で解錠できます。**完全ローカル**で動作し、
Apple ID や Google アカウントには一切依存しません。

必要なもの: Touch ID 搭載の Mac と Xcode Command Line Tools（未導入なら `xcode-select --install`）。

1. 「すべての登録を管理」→ 設定画面の **「Touch ID 解錠」** を見る
2. 未設定なら、実行すべきコマンドが表示されます。**コピー**してターミナルで実行
   ```sh
   ./native/install.sh
   ```
   拡張 ID を調べる必要はありません。スクリプトが自分で算出します
3. **Chrome を再起動**（拡張の再読み込みだけでは反映されません）
4. 設定画面に戻って **「確認」** → 見つかれば **「Touch ID 解錠を有効化」** が出ます

仕組みの詳細は [`native/README.md`](native/README.md) を参照。

> ⚠️ **セキュリティ上の注意**: 鍵は login キーチェーンに保存され、**ハードウェア保護ではありません**
> （ハードウェア保護には有料 Apple Developer 署名が必要なため）。このユーザー権限で
> コード実行できる攻撃者は Touch ID を経ずに鍵を取り出せます。**at-rest 強度はマスターパスワード
> のみ運用に劣る**、あくまで利便性向けの機能と位置づけてください。

## 3. 日常の使い方

### 資格情報を登録する

**登録を忘れても拡張が気づきます。** ブラウザのダイアログから認証が通ったのに未登録だと、
「このサイトを登録しますか？」と提案します（通知＋ツールバーの青い `+`）。
アイコンをクリックすると **host が埋まったフォーム**が出るので、ユーザ名とパスワードを
入れて「登録」を押せば完了です。

- パスワードが変わったサイトでは「**登録した資格情報が古いようです**」として提案し、
  既存のユーザ名を埋めた状態で出ます
- 「今回はしない」を押すと、そのサイトについては**ブラウザを閉じるまで**聞きません
- 手で登録することもできます（ポップアップの「このサイトの資格情報を登録」、
  または設定画面のフォーム）

> 💡 ダイアログに打った内容をそのまま取り込むことはできません。**ブラウザが認証ダイアログに
> 入れた資格情報は、拡張からは観測できない**ためです（Chrome が拡張の観測点より下流で
> 差し込みます）。そのため入力は2回になりますが、一度登録すれば以降は自動入力されます。

以降、登録済みのサイトでは Basic 認証のダイアログが出る前に自動でログインされます。

### 施錠と解錠

ブラウザを再起動すると施錠されます。次に認証が必要になった時点で **Touch ID が出る**ので、
指を置けばそのページがそのまま開きます（リロード不要）。

キャンセルしたり15秒放置したりすると、ブラウザ標準のダイアログに切り替わり、
通知とツールバーの赤い `!` でお知らせします。**以降は繰り返し聞きません** —
アイコンから明示的に解錠すると元の動作に戻ります。

### host の指定方法

| 指定 | マッチ対象 |
|---|---|
| `example.com` | `example.com`（デフォルトポート） |
| `example.com:8443` | ポート 8443 |
| `*.example.com` | `example.com` および全サブドメイン |

完全一致がワイルドカードより優先されます。

**URL をそのまま貼っても構いません。** `https://example.com/admin` のように入力すると
保存時に `example.com` へ自動で整えます（入力欄からフォーカスを外した時点で表示も変わります）。

### 常にハードリロードする

設定画面のフォームで「**このサイトは常にハードリロードする**」にチェックを入れると、
その host でキャッシュから返ってきたときに自動で再取得します。Basic 認証のかかった
開発サーバで古いレスポンスを掴まされたくないときに使います。一覧の「再取得」列に ✓ が付きます。

### 動作確認（任意）

同梱のローカルサーバで試せます（Node が必要）。

1. `node tools/local-401-server.js` を起動
2. `http://localhost:8765/` を開き、ダイアログに `user` / `passwd` を入力
3. `{"authenticated": true}` が表示され、**「このサイトを登録しますか？」**の通知が出る
4. 拡張アイコンから `user` / `passwd` を入力して「登録」
5. もう一度開くと、ダイアログが出ずに表示される

> 💡 realm はサーバの起動ごとに変わります。やり直すときは**サーバを再起動**してください。
> Chrome は認証情報を realm 単位でキャッシュするので、そうしないと 2 回目以降
> ダイアログが出ません。逆に、空のまま閉じた資格情報がキャッシュに残って
> 認証が通らなくなった場合は、**Chrome の再起動**で消えます。

## 4. 資格情報の受け渡し

設定画面から、登録済みの資格情報をファイルに書き出したり読み込んだりできます。
**自分のバックアップ**にも、**必要な分だけ他の人に渡す**のにも使えます。

### エクスポート

1. 設定画面を開く（解錠が必要です）
2. 一覧で、**渡したい行だけチェック**を残す（既定は全選択）
3. 「エクスポート」カードで**エクスポート用パスフレーズ**を入力（確認用にもう一度）
4. 「エクスポート」を押すと JSON ファイルがダウンロードされます

> ⚠️ **他の人に渡す場合は、マスターパスワードとは違う文字列にしてください。**
> マスターパスワードを使い回すと、ファイルを渡すことが「自分の金庫の鍵を渡す」ことになります。
>
> ⚠️ **ファイルとパスフレーズは別の経路で渡してください。** 同じチャットに両方を貼らないでください。

「暗号化せず平文で書き出す」チェックもあります。他ツールへの移行や内容確認に使えますが、
**ファイルを開けば誰でもパスワードを読めます**。ファイル名に `-PLAINTEXT` が付きます。

### インポート

1. 「インポート」カードでファイルを選び「読み込む」を押す（暗号化ファイルならパスフレーズを聞かれます）
2. 同じ host が既に登録されていた場合は一覧が出ます。
   **チェックした行だけが相手の内容で上書き**され、チェックを外した行は今の登録が残ります
3. 「取り込む」を押すと「取り込み / スキップ / 上書き」の件数が表示されます

既定では**上書きしません**。意図せず自分の資格情報が置き換わることはありません。
「常にハードリロード」は端末ごとの設定なので、エクスポートには含まれず、上書きしても引き継がれます。

## 5. 困ったとき

| 症状 | 対処 |
|---|---|
| 自動入力されずダイアログが出る | host が一致しているか / 解錠済みか確認。一覧の Host 列が `example.com:8443` の形（スキームやパスを含まない）になっているか |
| 登録を提案してくれない | 既に登録済みで自動入力が成功した場合は出ません（提案の出番がないため）。「今回はしない」を押した場合はブラウザを閉じるまで出ません |
| 一度入れたら以後ダイアログが出ない | Chrome が資格情報をキャッシュ。シークレットウィンドウか再起動で再現 |
| ツールバーに赤い `!` が出ている | 自動解錠に失敗しています。アイコンから解錠してください |
| 解錠したのに Touch ID が出ない | 一度失敗すると、明示的に解錠するまで再び聞きません（仕様） |
| `Specified native messaging host not found` | `./native/install.sh` を実行したか / Chrome を**再起動**したか |
| 登録していないサイトでも Touch ID が出る | 施錠中は「その host の登録があるか」を判定できないための仕様です。キャンセルすれば以降は聞きません |
| Touch ID が出ない | システム設定 > Touch ID とパスコード を確認 |
| インポートで「対応していないファイル形式」 | この拡張がエクスポートしたファイルか確認してください |
| Chrome を再起動するたびに拡張が消える | リポジトリのルートを読み込んでいませんか。`extension/` を指定してください |

## 6. v0.2.x からの移行

**新規に導入する方には関係ありません。** v0.2.x から上げるときは、順序を守らないと
保存データが失われます。

v0.3.0 で拡張 ID を固定した関係で、**アップグレード時に一度だけ ID が変わります**。
Chrome は ID ごとに保存領域を分けているため、旧 ID のデータは新しい拡張から読めません。

1. **先に旧バージョンの登録内容を控える**（v0.2.x にエクスポート機能はありません）。
   件数が多い場合は、新しい版を**別フォルダに追加で読み込み**、旧拡張の設定画面を見ながら
   登録し直すのが確実です
2. **`chrome://extensions` で旧バージョンの拡張を「削除」する**

   > ⚠️ ここで「再読み込み」を押してはいけません。ID が変わるため、Chrome のプロファイルに
   > **旧 ID の登録が残ったまま新 ID の登録が追加され**、同じフォルダを指す登録が2つになります。
   > この状態になると Chrome を再起動するたびに拡張が消えます。

3. フォルダを最新に更新し、「パッケージ化されていない拡張機能を読み込む」で **`extension/`** を読み込む
4. **Chrome を一度再起動し、拡張が消えないことを確認する**
5. マスターパスワードを設定し直し、控えた資格情報を登録する
6. Touch ID を使っている場合は `./native/install.sh` を実行し、**Chrome を再起動**してから有効化し直す

> 🔁 移行が済んだあとは、この作業は二度と必要ありません。以降は ID が固定されるので、
> フォルダを移動しても入れ直してもデータは残ります。

## セキュリティ

- パスワードは平文で保存しません。鍵はマスターパスワードから都度導出します（鍵自体は保存しない）。
- 解錠状態はメモリのみ（`storage.session`）。ブラウザ終了で破棄されます。
- **通信中の資格情報は観測しません。** 拡張がパスワードに触れるのは、あなたが拡張の
  フォームに入力した時点だけです。
- マスターパスワードを忘れると復号できません。設定画面の **リセット** で全削除のみ可能です。
- content script からはアクセスできません（拡張内の信頼コンテキストのみ）。

## 開発

拡張本体は**ビルド不要**です。以下は開発時のみ使います。

```sh
pnpm install                      # eslint（devDependency のみ）
pnpm lint
pnpm test                         # 純粋ロジックの自動テスト
node tools/local-401-server.js    # 動作確認用の 401 サーバ（user / passwd）
```

`http://localhost:8765/` で単発の Basic 認証、`/multi` で 401 を返すサブリソースを
5つ持つページを返します。

## 制限事項 / 今後
- プロキシ認証（`isProxy`）の自動供給は対象外（コード上に枠のみ）
- `chrome.storage.sync` による端末間同期は未対応（エクスポート / インポートで代替）
- ハードウェア保護の Touch ID は未対応（有料 Apple Developer 署名が必要なため）
- マスターパスワードを忘れた場合の復旧手段は未実装（リセット＝全削除のみ）
- 「施錠しない」設定は未実装（仕様は `PROJECT_SPEC.md` に確定済み）
